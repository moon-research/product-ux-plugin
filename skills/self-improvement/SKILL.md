# Improve Product UX from evidence

Fix the boundary that lost useful information. Project-specific product work stays in the project; this skill improves the reusable plugin.

1. Capture the actual request/brief, context supplied, return, artifact/change and observed consequence. Use [the diagnosis guide](references/diagnosis.md). A remembered explanation is an assumption until supported or reproduced.
2. Read the current implicated skill and its callers, references, room contract and consumers. State what the sender knew, what crossed the boundary, what the receiver saw and what the next step needed. Locate the missing/incorrect contract rather than blaming the agent.
3. Propose the smallest correction at that layer. For accumulated feedback, group related evidence and prioritize recurring or serious failures. A local correction to the next brief can proceed in project scope; a reusable plugin change belongs in the maintained source repository.
4. Apply source changes within the user's existing authorization. If the work is only a diagnosis, or the proposed change expands scope, present the concrete fix and obtain the missing decision first. Do not re-request approval for the focused source fix the user already asked you to make.
5. Re-run the observed scenario and relevant package checks. Record a meaningful regression or reusable probe when it prevents recurrence; avoid tests that merely match headings. Preserve evidence limits and avoid broad unrelated workflow edits.
6. Update the version in root/Claude/Codex manifests together, update release notes and affected contributor guidance, and verify packaging. Follow [shipping the correction](references/shipping.md) for installed snapshot refresh and fresh-session validation.

Close the learning loop: the project's local note points to the adopted plugin change; the plugin change cites redacted local evidence. Explain what changed and why, the scenario outcome, source/PR state, installed version and what still needs a host reload.

Example: the designer knew the accepted draft and source component, but the return contract carried only a canvas link. Improve the design-to-build handoff slot and its consumer; do not rewrite the entire requirements skill, add a new orchestration framework or copy customer-specific paths into defaults.

Source edits, pushed code, installed snapshots and a running session's loaded skills are different states. Report each accurately.
