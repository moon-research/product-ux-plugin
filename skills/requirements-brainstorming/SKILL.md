# Requirements brainstorming

Turn the user's idea and available evidence into decisions a designer can act on. Use the normal conversational approach: understand the context, frame meaningful choices, explore alternatives, record decisions and review the resulting brief.

1. Read existing project instructions, brief, research and accepted decisions. For Product Graph input, use [the input guide](references/product-graph-input.md). An existing clear brief may already answer most questions.
2. Establish the audience, problem, intended action and current constraint. State the few unresolved angles that matter; let the user change that agenda. Ask one material question at a time. A question should describe the situation, real alternatives, their consequences and your recommendation. Continue independent investigation while waiting.
3. Show decisions concretely: an example headline, a short user journey or an offer comparison is easier to assess than an abstract label. Explore two or three whole approaches when the choice is consequential. Scale depth to the request; a single section can need only a paragraph.
4. Capture decisions and reasons as they happen, including exclusions and assumptions. Clearly distinguish supplied evidence, observed facts and illustrative examples. Do not invent a winning offer or measured result to fill a gap.
5. Write or update the [requirements handoff](references/requirements-handoff.md) in the project's existing documentation home. Review it with the user. Preserve decisions already made; resolve missing acceptance criteria before the affected implementation.

The result names what the person does and sees, why the product/page matters, what is in scope and what remains open. It is ready for `ux-brainstorming`; it need not be a technical implementation plan. If the user only wants the requirements, end there.

Example: 22 researched angles with no chosen offer need an evidence-backed shortlist and an offer decision before landing-page copy. A supplied, accepted offer brief can proceed directly to UX work.

This workflow is bundled here. Superdev, Product Graph rooms and a specific model or agent runtime are not required.
